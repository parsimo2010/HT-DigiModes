## What the key does

On an idle, simplex FM VFO with scan off, holding physical SK1 (the top monitor side key) arms physical PTT. A PTT press requests one 360 ms sequence at power level zero. It includes a preamble, a link setup from the reference fixture AB1CDE to AB2CDE, six data stream frames with payload `00 01 02 03 04 05 06 07 08 09 0a 0b 0c 0d 0e 0f`, and an end marker. The last frame carries the end bit. Holding PTT after completion leaves the radio in receive. Releasing either key early ends the burst. The 10 ms radio task checks a 650 ms elapsed-time ceiling that includes modem startup and tail. Timing and power at the antenna connector await measurement.

The build uses RadioFoundry's existing VFO and TX screen. It reserves the radio core's transmitter for the bench session, checks the board's transmit permission and feeds the HR_C6000 provider twelve chunks of 144 symbols. The stored vector uses the lab's reference identities. This is a contained data test. M17 microphone audio, Codec2 speech and M17 decoding on the handheld are future work. The private merged codec supports stock-format DMR audio.

## Evidence

- A fresh checkout of pinned RadioFoundry plus both patches reproduced the private candidate byte for byte. The ARM toolchain was GCC 14.2.1. The feature-on and feature-off builds linked. The feature-on build emitted zero compiler warnings.
- RadioFoundry’s host suite passed. Its optional private Tier III replay and standard SNMP MIB check skipped. The new radio-core test passed 45 checks, including the actual chunks queued to a simulated modem, ordinary and host-audio PTT refusal, failure to key, inhibit, split frequency, each physical release, underrun, timeout across clock wrap, end-of-burst unkey and held PTT. The eight lab unit tests passed. The previous M17 frame diagnostic also passed in ARM emulation on the new merged bytes.
- The 432 bytes at `0x080B0000` in the private image matched every byte emitted by the radio-core host test. At 960 ksample/s the actual lab receiver decoded the sequence with simulated root-raised-cosine transmit roll-off 0.5, then independently at 0.2 to represent the chip’s nominal DMR shaping. GNU Radio 3.10.12.0 and gr-m17 `c6ec482121f964d446fab4e247916b0942f6d4b2` reported TYPE 0003 and frames `0000 0001 0002 0003 0004 8005` in both cases. The simulator assumed a centered signal and ±800/±2400 Hz deviations. It did not model the individual radio’s frequency error or measure its RF.
- The receiver captured simulated input byte for byte, rejected an incorrect required frame count and preserved an existing capture when the same output path was supplied again.

## Repeat on the computer

Use the [pinned toolchain](dm1701-build.md), the [GNU Radio environment](m17-reference.md), SciPy and python3-unicorn. Set `STOCK_CSV` to the verified private stock file and run from the lab root using a fresh worktree path.

```bash
set -eu
umask 077
lab=$PWD
source ~/ht-m17/env.sh
cd ~/ht-m17/RadioFoundry
export RFOUNDRY_THIRD_PARTY="$PWD/third_party"
tools/worktree.sh add ../rf-m17-ptt-verify --detach bac4b209cd8ade5de3040ed7df11753b9e0ceacc
cd ../rf-m17-ptt-verify
git -c user.name='HT DigiModes Lab' -c user.email='lab@localhost' am --committer-date-is-author-date \
  "$lab/firmware/radiofoundry/m17-frame-test.patch" "$lab/firmware/radiofoundry/m17-ptt-test.patch"
test "$(git rev-parse HEAD)" = 4c6a56e5bbbf0f1c71be94b8f8790fa9b956298c
export SOURCE_DATE_EPOCH=$(git show -s --format=%ct HEAD)
make -j8 -C tests/host
capture=$(mktemp)
tests/host/radioCoreTestM17 --capture "$capture"
make -j8 BOARD=dm1701 BUILD=build/ptt CONFIG_M17_FRAME_TEST=y CONFIG_M17_PTT_TEST=y 'OPT=-Os -frandom-seed=dm1701'
img=build/ptt/rfoundry_dm1701
python3 tools/codec_extract.py --board dm1701 --stock "${STOCK_CSV:?Set private stock path}" --image "$img.bin" -o "${img}_codec.bin"
sha256sum "$img.bin" "${img}_codec.bin"
python3 "$lab/scripts/check_m17_image.py" "${img}_codec.bin" "$img.elf"
python3 "$lab/scripts/check_m17_ptt.py" "${img}_codec.bin" "$img.elf" "$capture"
python3 tools/stm32_dfu.py --model dm1701 --dry-run "${img}_codec.bin"
cd "$lab"
python3 -m unittest discover -s tests -v
```

## First bench run

1. Complete the [RF fixture and stock-baseline worksheet](dm1701-bench.md) while stock is installed. Confirm the simplex frequency, 50-ohm load power rating, coupling and attenuation at that frequency, connected receive port, and worst-case SDR input power with margin. The LibreSDR has already [passed its receive sample benchmark](../hardware/libresdr/qualification.md).
2. After a separately approved application-only install, boot with PTT released. Before settings changes or RF, save the factory security registers in the private backup and verify the complete, repeatable readback per LAB-008. The tested recovery firmware is Radioddity V02.03 CSV.
3. For the separately approved RF test, use one local key-down with the SDR already recording on the same frequency. Run the receiver from the lab root in WSL, using the verified receive port and a new filename in the private capture directory. The capture starts when the receiver starts streaming.

```bash
source ~/ht-m17/env.sh
args="type=b200,fw=$UHD_IMAGES_DIR/usrp_b200_fw.hex,fpga=$UHD_IMAGES_DIR/usrp_b210_fpga.bin"
python3 scripts/m17_rx.py --sdr-args "$args" --rate 960000 --seconds 10 \
  --antenna "${RX_PORT:?Set the verified channel 0 receive port}" \
  --frequency-hz "${FREQ_HZ:?Set the agreed simplex frequency in Hz}" \
  --capture-iq "${CAPTURE:?Set a new private .cf32 path}" --check-ramp --expect-frames 6
```

A complete run shows the fixture link setup, the six frame numbers listed above, the 96-byte payload hash and return to receive while PTT is still held. Preserve the IQ and decoder log for frequency, symbol timing, occupied bandwidth and key-up/down measurements. A partial or absent decode leaves this bench gate open.
